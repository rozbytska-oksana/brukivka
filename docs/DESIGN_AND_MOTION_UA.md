# Дизайн, дві теми й анімації

## Візуальна основа

Зберегти характер початкового сайту: натуральний камінь, виразна типографіка, великі фото, повітря, заокруглені картки, графіт/пісок/теракота. Шрифти референсу — Manrope для тексту, Unbounded для акцентних заголовків. Не робити шаблонний SaaS-лендинг із сторонніми ілюстраціями.

Базові кольори з CSS snapshot: темний фон #0e0e0f, картки #1a1a1d, текст #f3f0ea, акцент #d4703f; світлий фон #f3ebdd, картки #fbf6ec, текст #2b2118, акцент #c0602f. Це вихідні tokens: контраст інтерактивних станів перевірити в обох темах.

Початкова тема — темна; кнопка у шапці перемикає і зберігає вибір. Не фарбувати фотографії CSS-фільтрами. Повні стани кнопок/форм/меню/галереї розробити для обох тем. Немає спалаху іншої теми при refresh чи навігації.

## Логотип і favicon — оновлення 20.10.2026

Збережено мотив оригінального logo.png: будинок і два діагонально штриховані камені. Новий знак має геометричний дах, виразні шви та дві плашки з діагональним розрізом. Напис BRUKIVKA накреслено окремими векторними контурами зі скошеними кутами, акцентна крапка повторює форму каменю. Це нове накреслення, а не шрифт або масштабований PNG оригіналу.

Один BrandLogo використовується у header/footer; на mobile знак залишається видимим. Кольори inline SVG — currentColor / --accent, без окремих клієнтських theme-станів; доступна назва задається посиланням «BRUKIVKA — головна», декоративний SVG прихований від screen reader. Футер використовує збільшений варіант, hover змінює колір через наявні правила бренд-посилань. У forced colors усі частини можуть успадкувати currentColor. Геометрія — app/assets/brand/geometry.json, статичні SVG — public/brand, аркуш обох палітр — BRAND_PREVIEW.png.

Favicon використовує спрощений знак із суцільними каменями на графітовій підкладці: деталі не губляться у 16px, силует читається у світлих і темних вкладках. Створено SVG, PNG 16/32px, ICO із 16/32/48px та Apple touch icon 180px; окрема 512px іконка є в public/brand. Це не PWA й не додавання service worker. Експорт повторюється через npm run brand:prepare без додаткових пакетів. Старий public/images/logo.png та фотографії залишаються оригінальними.

## Анімації з референсу

| Ефект                   | Реалізація                                                                  |
| ----------------------- | --------------------------------------------------------------------------- |
| Reveal секцій           | Opacity + translateY, тільки при вході конкретного блока в viewport         |
| Послідовна поява карток | Затримки 40–70 мс у видимому рядку, без накопичення на весь каталог         |
| Меню                    | Поява overlay/панелі та пунктів; Vue Transition, коректний focus management |
| Зміна теми              | Кругове розкриття від кнопки; View Transitions як progressive enhancement   |
| Header                  | Зміна фону/тіні при скролі без зміни висоти                                 |
| Прогрес скролу          | Тонка смужка вгорі, перерахунок для поточного маршруту                      |
| Галерея                 | Плавне відкриття, перехід фото, свайпи, зрозуміле очікування завантаження   |
| Hover                   | Делікатна реакція карток/кнопок, тільки на відповідних пристроях            |

У source reveal має 28 px / 900 мс, theme circle 750 мс. Для нового сайту можна скоротити reveal до 12–20 px / 350–550 мс; візуальну відповідність і відчуття швидкості перевірити поруч із джерелом. Для hover не обрізати й не обертати товарні фото. Світлову пляму за курсором використовувати лише якщо вона не спотворює сприйняття матеріалу. Рухома мозаїка, clip-path для об’єктів і безкінечні декоративні цикли не є обов’язковими.

Не приховувати hero/LCP за довгим вступом. Контент видимий без JS; приховані reveal-стани вмикати лише після успішної ініціалізації. При помилці observer або фокусуванні контент відкривається. Один reveal за поточне монтування; після переходу на нову сторінку її елементи отримують власний observer. Звичайний скрол не перехоплювати.

prefers-reduced-motion: відсутні рух, stagger, circle transition і лічильники; весь контент одразу видимий. Не анімувати height/width/позиції великих блоків. Основний рух — transform/opacity. Не підключати GSAP/AOS лише заради цих ефектів.

## Адаптивність і QA

Mobile-first; лише два брекпоінти ширини: medium 768px та x-large 1200px, через спільні SCSS-змінні/міксини в app/assets/styles/_breakpoints.scss. Мобільна композиція задається базово; зміни вкладаються у відповідний селектор через @include bp.medium / bp.x-large. Перевірка 320/360/390/430/767/768/1024/1199/1200/1440/1920 px та проміжних ширин. Категорії й звичайна галерея: 1/2/3 колонки; палітра: 2/3/6. До 1200px використовується кнопка меню, від 1200px — повна навігація й телефон. Контроль overflow, довгих підписів, safe area, мобільної клавіатури, portrait/landscape. Реальні iPhone Safari та Android Chrome доповнюють desktop-емуляцію.

Перевірити повільний/швидкий скрол, Back/Forward, refresh внутрішнього URL, переходи між категоріями, reduced motion, вимкнений JS, клавіатуру та швидкі повторні натискання на меню/галерею. Немає завислого overlay, scroll lock, прихованих карток або дубльованих listeners. Сучасність підтверджується узгодженим дизайном і плавними взаємодіями, а не максимальною кількістю ефектів.

## Оновлений лендинг — 20.10.2026

Замість окремих інформаційних сторінок реалізовано одну композицію: hero з двокольоровим мощенням «Луска» й трьома зразками → фактичні навігаційні числа (6 категорій / 18 зразків / 14 фото) → категорії → фактура каменю → всі зразки → об’єкти → послуги/кроки/склад → звернення → контакти.

Прибрано порожню аркову рамку першого екрана й дублюючі CTA на повні інформаційні сторінки. Для робіт — велике фото поруч із двома меншими; для зразків — компактна палітра; послуги доповнено реальними фото. Додаткові зразки/об’єкти та склад — native details, що зберігає доступ до всіх фото без JS. Фотографії скрізь вміщуються повністю через contain; обробки кольору й перекодування немає.

Рух: коротка послідовна поява заголовка; декоративне коло у hero обертається від фактичного скролу; reveal має варіанти зліва/справа/знизу; стрілки карток реагують на hover; details змінює стан іконки. Немає нескінченних автоматичних циклів або перехоплення прокручування. useScrollScene очищає rAF/listeners, useReveal враховує відкриття details і зміну reduced motion. LCP-фото видиме одразу, eager/high priority. Наявний круговий перехід теми збережено.

Nuxt використовує стандартне очікування page:loading:end перед переходом до hash на іншій сторінці. Scroll offset задає один scroll-padding-top; подвійного offset через додатковий scroll-margin немає. Reduced motion вимикає smooth scroll та всі декоративні рухи. Візуальне/мобільне приймання цих змін ще потребує доступного браузера.

## Поточний головний банер: похила сітка — 20.10.2026

За новим дорученням користувачки попередню праву картку фото та декоративне коло замінено повноширинним фоном із каменю. Це актуальний варіант hero; попередній опис вище залишається історією змін.

- HeroBanner містить заголовок, CTA й керування паузою. HeroStoneGrid — сім рядів під кутом −12°, кожен із двох однакових груп по вісім плиток. Парні ряди рухаються у зворотному напрямку, швидкості трохи різняться. Перехід між повтореннями будується на translateX(−50%) двох рівних груп, включно з відступом; порожній проміжок у циклі не закладається.
- Повторюються лише вісім оригінальних JPG. Замість дрібних 90px thumbnails використано наявні великі фото; файли не змінюються, немає blur, CSS-фільтрів або обрізання фото всередині плиток. Вся декоративна площина нахилена за прямим запитом користувачки.
- Графітовий/пісочний градієнт читає --bg-rgb відповідної теми. Під текстом він щільніший, праворуч відкриває сітку. Основний текст і дрібні підписи використовують повний колір --text. Світлий/темний варіанти застосовуються тією ж ранньою ініціалізацією теми.
- Анімація автоматична, циклічна, але має явну кнопку паузи. useBackgroundMotion також зупиняє її поза viewport та в прихованій вкладці. Ручна пауза не скидається при поверненні у viewport. Observer і listeners очищаються при демонтажі.
- SSR і перший client render нерухомі, рух вмикається після mount. Без JS сітка статична, контент і CTA доступні. Prefers-reduced-motion вимикає рух CSS і composable; кнопка зайвого керування не показується. Декоративні дублікати приховані від assistive technology через aria-hidden.
- Перший фоновий ресурс eager/high priority, решта — eager/low для завантаження до входу плиток у кадр; браузер може повторно використовувати однакові URL. Сирий сумарний розмір восьми оригіналів — 992 510 байтів. Це розмір файлів, а не виміряний network/LCP/FPS результат.

Залишається browser QA: шов циклу, баланс видимого фону й тексту в обох темах, пауза/відновлення, зміна reduced motion, перегляд на mobile, фактичні LCP/FPS. Вбудований браузер досі недоступний; ці сценарії не позначені перевіреними.

Порядок фото у кожному ряді тепер задає app/data/hero-stone-rows.ts: це різні циклічні перестановки, а не зсув однієї послідовності. Пари сусідніх каменів, включно зі стиком циклу, не повторюються між рядами; це запобігає вирівнюванню однакових довгих послідовностей. Детерміновані дані зберігають узгодженість SSR/hydration.

## Читабельність і підтверджений досвід — 20.10.2026

Основний текст використовує --text-body: 1.125rem (18 px за стандартних налаштувань браузера); підписи, навігація, лейби, кнопки й допоміжний текст — --text-small: 1rem (16 px). Мобільні правила не зменшують ці розміри. Значення в rem поважають налаштування користувача; збільшений шрифт сам по собі не підтверджує відповідність WCAG.

Довгі назви, адреси й пошта можуть переноситися. Інформаційні показники на вузькому екрані переходять у вертикальний список; нижні елементи hero розташовані в нормальному потоці й можуть переноситися. Для посилань меню, контактів, breadcrumbs та кнопки паузи задано мінімальну висоту 44 px; основні кнопки й поля мають мінімум 52 px. Фактичну відсутність перекриттів при збільшенні тексту слід перевірити в браузері.

Користувачка підтвердила роботу в Житомирі з 2001 року. У hero додано статичну лейбу «Житомир · працюємо з 2001 року» на непрозорій тематичній поверхні. Вона читається без очікування рухомого рядка; рік також є у footer та LocalBusiness JSON-LD. Єдине джерело року — businessContacts.sinceYear. Точний день заснування та інші історичні твердження не додавалися.

За наступним запитом користувачки крапку лейби доповнено двома тонкими кільцями: масштабування й згасання за 2,8 с, зсув між хвилями 1,4 с. Текст лейби нерухомий. Колір — тематичний --accent; псевдоелементи не впливають на компонування. Хвилі використовують той самий running-стан, що й сітка каменю: спільна пауза, видимість секції/вкладки та reduced motion. Без JS або при reduced motion залишається нерухома крапка.

## Обкладинки категорій без рамок — 20.10.2026

За новим запитом користувачки шість карток категорій зі скриншота використовують object-fit: cover з центральним позиціюванням. Прибрано padding 18 px, зовнішній border і світлу підкладку; фото заповнює контейнер 4:3 до заокруглених країв. Це погоджений виняток із початкового правила contain для обкладинок категорій. Біле тло, яке є частиною оригінального фото, не ретушується. Оригінальні файли, галерейні фото та повний перегляд не змінюються.

## Cover в інших блоках і реакції на взаємодію — 20.10.2026

Наступне уточнення користувачки поширює cover на решту фотоблоків: прев’ю каменю, об’єктів, складу й категорійних галерей, послуги, композицію про камінь, маленькі зразки звернення та декоративну hero-сітку. Світлі відступи/рамки фотографій прибрано; підкладки використовують surface. У розгорнутому lightbox збережено contain для повного фото, а підкладку замінено на bg поточної теми. Оригінальні байти/кольори фото не змінюються.

Картки категорій і галерей мають легке підняття фоторамки на 4 px, тематичну тінь, тонке акцентне обведення й зсув стрілки. Анімується вкладена рамка, а не зовнішній data-reveal, щоб не конфліктувати з появою при прокручуванні. Фотографії додатково не збільшуються на hover. Кнопки отримали підняття на 2 px та акцентне світіння; текстові посилання — підкреслення або тематичне заповнення, summary — виділення й зміну іконки, поля — акцентну межу. Статичні картки послуг залишаються інформаційними.

Клавіатурний focus-visible має відповідне акцентне виділення й видимий outline. Hover обмежено пристроями з hover; переміщення — також prefers-reduced-motion: no-preference. При reduced motion кольори/обведення змінюються без анімованих переходів і підняття. Вимкнені кнопки/поля не отримують активних hover-ефектів. Нових залежностей або JS-обробників вказівника немає.

## Поточний hover фотокарток: легке наближення — 20.10.2026

Користувачка відхилила рамку й попередній hover фотокарток. У CategoryCard та GalleryPhoto прибрано акцентний псевдоелемент, тінь, підняття контейнера та рух/зміну кольору стрілки від наведення. Тепер лише саме зображення плавно збільшується до scale(1.045) за 0,5 с, а контейнер із overflow: hidden залишається нерухомим. Це актуальне рішення замість підняття фоторамки з попереднього розділу. Клавіатурний outline та акцент стрілки при focus-visible збережені; при reduced motion масштабування вимкнене. Повний lightbox не масштабується від hover.

## Галерея як одна відкрита добірка — 20.10.2026

У спільному ImageGallery прибрано лінію й повноширинний рядок «Переглянути ще…». Замість них — компактне керування по центру, без рамки/підкладки, зі стрілкою. При відкритті керування між фото приховується, додаткові зображення продовжують сітку з тим самим міжрядковим відступом. Кнопка «Згорнути добірку» розташована в DOM після останнього фото. Це стосується всіх використань previewCount, зокрема каменю та робіт.

Після відкриття фокус переходить на перше додаткове фото, після згортання — на початкове керування. Native details збережено як fallback без JS: усі фото можна розгорнути й згорнути через summary, а підпис змінюється CSS-правилом [open]. Перенесення керування під фото вмикається після mount, без зміни початкової SSR-розмітки. Reduced motion вимикає декоративні переходи; жодної анімації висоти немає.

## Текстові CTA без заливки блока — 20.10.2026

За скриншотом користувачки прибрано прямокутне заповнення .text-link. У всіх п’яти текстових CTA акцентний колір проходить зліва направо лише по літерах/стрілці за 0,45 с: градієнт обрізається по тексту вкладеного .text-link-label, фон посилання порожній. Розміри й підкреслення не змінюються. Такий самий стан доступний через focus-visible зі збереженням outline. Без підтримки background-clip: text колір перемикається звичайним CSS; forced colors залишає читабельний LinkText, reduced motion вимикає перехід. Дубльованих текстів або JS-анімації немає.

## «За лаштунками»: помітне прев’ю складу — 20.10.2026

Попередній тонкий рядок під кроками замовлення замінено WarehouseGallery: окрема тематична картка з реальним фото виробництва, більшим заголовком, коротким описом і явною дією «Переглянути 6 фото». Уся summary-картка інтерактивна; акцентний елемент дії — span, без вкладених кнопок. На mobile фото розміщене над текстом. Фото заповнює рамку через cover, без світлих відступів; hover дає лише погоджене наближення.

Після відкриття картку-прев’ю замінює добірка всіх шести фото з заголовком і уточненням наявності; «Згорнути добірку» розташовано внизу. Фокус переходить до першого фото й повертається до прев’ю після згортання. Спільну механіку з ImageGallery винесено в useGalleryDisclosure. Без JS працює native details/summary, підписи змінюються CSS; повні оригінали доступні через галерею.

Уточнення користувачки: інтерактивною є лише кнопка. Прев’ю, заголовок та опис тепер звичайний вміст section, без обробника кліку, pointer-курсора чи масштабування фото від hover. Окрема button «Переглянути 6 фото» відкриває details під карткою; її aria-controls/aria-expanded описують зв’язок і стан. Заголовок/прев’ю залишаються видимими, кнопка відкриття прихована на час перегляду; згортання знизу повертає фокус саме на кнопку. useGalleryDisclosure приймає необов’язковий ref для повернення фокусу. Без JS доступний окремий компактний summary, а решта картки також не клікабельна.

## Єдиний текстовий hover із підкресленням — 20.10.2026

У текстових CTA, меню, контактах/месенджерах, breadcrumbs, футері й керуванні галереями прибрано постійні підкреслення. .text-link та .link-effect використовують спільний .text-link-label: акцентний колір тексту й нижня лінія проходять зліва направо синхронно за 0,45 с. Лінія — окремий псевдоелемент з transform-origin: left, без зміни геометрії посилання; прямокутної заливки немає. Поточний пункт меню зберігає акцентний колір, лінія з’являється лише при hover/focus-visible. Старі окремі правила підкреслень видалені, у mobile-меню прибрано повноширинну hover-заливку та лінії під рядками посилань.

Клавіатурний focus-visible дає такий самий ефект із видимим outline. Reduced motion вимикає обидва переходи, forced colors зберігає читабельний текст і border-лінію; звичайна зміна кольору працює без background-clip. Hover обмежено пристроями з hover. Розміри інтерактивних цілей і видимі підписи збережено; анімація не потребує JS.
